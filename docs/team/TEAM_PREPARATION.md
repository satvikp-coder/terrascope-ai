# Team preparation — proposed roles, not assigned people

Official [participant FAQ](https://www.spaceappschallenge.org/resources/participant-faqs/), accessed 2026-10-18: maximum six participants, solo allowed, one team/one challenge, same registered local event for global judging. All must meet [global eligibility terms](https://www.spaceappschallenge.org/legal/). No team roster or account registration was inspected; Ahmedabad registration is owner-reported. Do not switch to Universal automatically.

| Role | Essential responsibility | Optional combination |
|---|---|---|
| Lead / integration | Compliance, scope, merge coordination and submission | Can own presentation |
| Remote sensing / GIS | Provenance, quality, units/geometry and scientific assumptions | Can combine with evaluation |
| Scientific validation | Independent references, uncertainty and metrics | Essential even without ML |
| Processing / backend | Authorized reproducible analysis and bounded local execution | Service optional; can combine with GIS |
| Visualization | Clear map/date/quality interactions | Simple UI; no dedicated React specialist required |
| Testing / documentation / presentation | Reproduction, failure checks, accurate narrative and submission | Shared by all, one accountable owner |

Names/availability/skills remain unassigned. A small team can combine roles; six people are not required. Owner should confirm actual availability, timezone, GitHub access and skills privately; no collaborator invitations are sent.

Onboarding: read README → rules → FINAL_DATA_READINESS → scientific limitations → evaluation plan → assigned backlog. Understand that full mask coverage is not flood validation. Confirm safe Git identity, no credential sharing and external data location. Record any proposed assumption with source, impact, owner and verification state.

Collaboration: one accountable owner per task; brief start/midday/end check-ins; blocker message includes observed failure, impact, attempted safe checks and requested help; urgent compliance/science uncertainty goes to lead immediately. Review science-affecting changes with the validation role and integrations with another teammate. Keep credentials in individual protected stores, not chat or screenshots. Use CONTRIBUTING and issue templates.

Registration checklist: every member's eligibility/consent, registered account, Ahmedabad selected, one team membership, total <=6, same challenge, team/project page, owner contact channel, local start/deadline confirmation and eventual submission receipt. All account-dependent boxes remain owner verification tasks. Do not claim a registered or fully staffed team from this plan alone.
