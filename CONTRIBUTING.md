# Contributing during preparation

This repository records NASA Space Apps 2026 research and preparation. Competition implementation is not open yet. Read [rules and boundaries](docs/COMPETITION_RULES_AND_BOUNDARIES.md). Do not contribute application features, algorithms/models, pipelines, finished UI or demos before verified official start and the owner's explicit build authorization.

Use small documentation changes with a source URL, access date and verification scope. Separate measured facts, published findings, hypotheses and unknowns. Preserve contradictory historical evidence and add an explicit superseding note rather than deleting useful records.

Never commit credentials, cookies, tokens, .env/.netrc, imagery, virtual environments, large reports or personal participant information. Keep bulk files on E:. Set a GitHub noreply commit email before contributing; inspect the staged diff. Cite borrowed work and verify its license; contributions must be compatible with Apache-2.0 and you must hold the necessary rights. Do not relicense external data or agency marks.

For future team work, assign one owner per task, request scientific review for measurement claims and peer review for integration. Report blockers with evidence, impact and a proposed next step, without secrets. Be respectful and protect participant privacy; escalate disputes to the team lead or event organizers through approved channels. No collaborator invitations are automatic.

Before pushing: check Markdown relative links, git diff --check, tracked paths/file sizes, source claims and permission category. Record substantive outcomes in PREPARATION_STATUS and HANDOFF. No paid integrations or application deployment.
